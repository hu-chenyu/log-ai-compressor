# 威胁模型

这份文档回答一个问题：**谁能让这个工具说错话、拿到它不该拿的数据，以及我们明确不防什么。**

它来自一次外部评审。那份评审指出：`web/server.py` 的模块 docstring 原先
以「**安全边界**」为标题，而它实际只挡住了一类攻击者 —— 剩下的那一类
没有被承认。一个把「边界为什么成立」当卖点的项目，却没画过威胁模型，
这是对称的漏洞。v2.11.4 起把它补上。

> 规矩：**新增一条防御之前，先在这张表里加一行它防的是谁**。
> 加不进去的，说明它不是防御，是巧合。

---

## 1. 对手清单

| # | 对手 | 能力 | 目标 |
| --- | --- | --- | --- |
| A | 远端网页 | 诱导用户浏览器访问本机服务 | 把本机日志内容读出去 |
| B | 网络上的其他主机 | 直接连 `127.0.0.1:8765` 或局域网地址 | 同上 |
| C | 本机同权限进程 | 直接调 CLI / MCP / HTTP | 读日志（**它本来就能读**） |
| D | 本机低权限进程 | 同 C，但服务以管理员运行时 | **权限升级** |
| E | 日志作者 | 在自己的服务里写任意文本 | 让工具得出错误结论 |
| F | 第三方依赖 | 通过供应链进入本进程 | 偷日志 / 改结论 |

---

## 2. 逐个对手的处置

### A. 远端网页（DNS rebinding）—— **防住了**

攻击者把自己控制的 `evil.test` 解析到 `127.0.0.1`，浏览器发出的是**同源**
请求（同源策略因此放行），但 `Host` 头是 `evil.test`。

| 防御 | 位置 |
| --- | --- |
| 回环绑定 `127.0.0.1` | `serve()` 默认参数 |
| `Host` 头白名单（只认 `127.0.0.1` / `localhost` / `::1`） | `_host_allowed()` 中间件 |

实测（2026-10-18 审计）：不校验时 `Host: evil.attacker.example` 与
`Host: localhost.evil.test:9999` 都返回 200 与完整负载；校验后均 403。

**两道门是独立的**：只绑回环挡不住 rebinding（浏览器就是从本机发出去的），
只校验 Host 而绑到 `0.0.0.0` 则挡不住局域网里的 B。

### B. 网络上的其他主机 —— **默认防住，靠回环绑定**

服务默认只绑回环，局域网里的机器连不上。

**唯一的例外是用户自己放开的**：`--allow-remote` / `serve(host="0.0.0.0")`。
此时 `serve()` 会**同时**关掉 Host 校验（否则用户反而够不着自己的服务）。
这是一个知情让步，代码里写明了它为什么这么做。

### C. 本机同权限进程 —— **不防，而且不需要防**

它可以直接跑 `log-ai-compressor analyze`，也可以直接
`curl 127.0.0.1:8765 -H "Host: 127.0.0.1:8765"` —— 两道门都放行。

**这不是漏洞。** 那个进程本来就能用当前用户的权限读当前用户能读到的所有
文件，本服务没有因此扩大它的能力。把它算成「被攻破」会让人误以为这里有
一条不存在的防线。

### D. 本机低权限进程 + 服务以管理员运行 —— **唯一的真实升级路径**

这是整张表里唯一「守不住但守不住就出事」的组合。

**结论：不要以提升权限运行本服务。** 正常用法下它只需要读日志文件的权限。

### E. 日志作者 —— **部分防住，剩下的是本工具的核心承诺**

| 攻击 | 处置 |
| --- | --- |
| 伪造一条「看起来像因果链」的行 | 链必须在**条目自己的堆栈里**且形如 `Caused by: <异常类名>`；消息里随口一句 `caused by: user input` 不满足形状 |
| 让相关性被当成因果 | `cooccurring` / `related_clusters` / `traces` **永远不提升置信档位**，且对外措辞禁止写成「导致了」 |
| 证据不足时诱导工具硬下结论 | 三档置信 + `INSUFFICIENT` 时读 `gaps`（缺什么），弃权算通过 |
| 出处被改 / 日志被换 | `verify` 重新读原文算 sha256，四档裁决 |

### F. 第三方依赖 —— **只靠「少依赖」，没有主动防御**

| 事实 | 后果 |
| --- | --- |
| 核心层（`core/` `export/`）**零第三方依赖**，仅 PyYAML | 供应链面极小 |
| Web / MCP / AI 层依赖 FastAPI、MCP SDK、httpx 等 | 这些只做**传输与协议**，不参与任何结论判定 |

**已知缺口（未修）**：没有 SAST、没有依赖漏洞扫描（`pip-audit` / `bandit` /
`codeql` 均未接入），也没有性能回归门禁。一个以「门禁可失效性」为卖点的
项目，**自身缺了行业标配门禁的一半** —— 这是外部评审指出的，写在这里免得
它继续隐形。

## 3. 数据边界

| 通道 | 出网？ |
| --- | --- |
| CLI / 核心分析 | **否**。全部在本机完成 |
| Web 服务 | **否**。只监听回环 |
| MCP 服务（stdio） | **否**。随客户端进程起 |
| AI 解读层（可选 extra） | **是**，但**必须显式配置** provider 与 Key 才启用；不配置则该层不存在 |

日志内容不出网这条承诺，由 `tests/test_publish_mcp_workflow.py` 之外的
若干门禁守着（`prove.py` 的「轻量安装：硬依赖不含 Web/MCP/AI」一条即
其中之一）。

---

## 4. 措辞纪律

以下措辞**禁止**出现在对外文档与代码注释里，除非同一处给出威胁模型范围：

- 「安全边界」而不说防的是谁
- 「只有本机能访问」（把 B 说成被防住了，其实只靠默认配置）
- 「本地运行」而不区分「不出网」与「不出网且无本地对手」

本仓库已经因为这条栽过一次：原 docstring 用了「安全边界」四个字，守的却
只有 DNS rebinding。`tests/test_web_traceback_contract.py` 之外，
`tests/test_threat_model_wording.py` 现在盯着它 —— 措辞改回「安全边界」
而没有威胁模型，测试必须红。
